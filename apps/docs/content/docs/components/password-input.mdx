## Usage

Complete [Installation](/docs/installation) once.

### Barrel

```tsx
import { PasswordInput, Field, FieldLabel } from "@ajnacloud/ui";
```

### Granular

```tsx
import { PasswordInput } from "@ajnacloud/ui/password-input";
import { Field, FieldLabel } from "@ajnacloud/ui/field";
```

### Basic usage

```tsx
<Field>
  <FieldLabel htmlFor="password">Password</FieldLabel>
  <PasswordInput
    id="password"
    name="password"
    autoComplete="current-password"
  />
</Field>
```

PasswordInput combines InputGroup's normal input with a visibility button. It starts masked and keeps the same native input when visibility changes, so its value, label, ref, and form identity remain connected.

Use FieldLabel or an accessible name for the password field. The eye icon is decorative; the button's accessible name describes its next action. The component owns type password/text, so type and render overrides are not part of its API.

## Examples

### Forms and autocomplete

Use `autoComplete="current-password"` for an existing credential and `"new-password"` when creating one. Native form attributes pass through. Form reset restores uncontrolled values but does not change visibility.

Disabled prevents editing and disables the reveal button. A read-only field prevents editing while still allowing its existing value to be revealed. An invalid field uses aria-invalid on the actual input; connect FieldError through aria-describedby as with other controls.

className and style target the input. containerProps configures the InputGroup wrapper, including its width, classes, and style. Group border, focus, invalid, and disabled treatments reuse InputGroup rather than introducing a second visual system.

## Accessibility

Pointer activation of the visibility control keeps focus in the input and restores its selection after the type changes. Keyboard users can Tab to the button and use Enter or Space to toggle; focus stays on the button for repeated activation. The forwarded ref points to the real input for normal form integration and focus management.

The visibility button has a visible keyboard focus treatment. Icons are hidden from assistive technology, and the input's original label continues to name the same element in both states. Reduced motion follows the existing InputGroup and Button styles.

## API reference

| Prop                    | Purpose                                 | Default        |
| ----------------------- | --------------------------------------- | -------------- |
| `value`, `defaultValue` | Controlled or initial input value       | Input defaults |
| `onValueChange`         | Value and Base UI change details        | —              |
| `onChange`              | Native DOM change callback              | —              |
| `showPasswordLabel`     | Action label while masked               | Show password  |
| `hidePasswordLabel`     | Action label while revealed             | Hide password  |
| `disabled`, `readOnly`  | Native editing states                   | false          |
| `containerProps`        | InputGroup wrapper props                | —              |
| Other props             | Input attributes, handlers, and styling | Input defaults |

IDs, labels, descriptions, autocomplete, form attributes, and validation attributes reach the native input. The component adds no strength meter, generator, confirmation field, or password validation service. Compose additional guidance through Field when your application needs it.
