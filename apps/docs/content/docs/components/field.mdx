## Usage

Complete [Installation](/docs/installation) once.

### Barrel

```tsx
import { Field, FieldLabel, FieldDescription, Input } from "@ajnacloud/ui";
```

### Granular

```tsx
import { Field, FieldLabel, FieldDescription } from "@ajnacloud/ui/field";
import { Input } from "@ajnacloud/ui/input";
```

### Basic usage

```tsx
<Field>
  <FieldLabel htmlFor="email">Email address</FieldLabel>
  <Input
    id="email"
    name="email"
    type="email"
    autoComplete="email"
    aria-describedby="email-help"
  />
  <FieldDescription id="email-help">
    We will send your invitation to this address.
  </FieldDescription>
</Field>
```

Field composes labels, controls, help text, and errors. Use FieldSet and FieldLegend for related choices, and FieldGroup for layout.

For [Select](/docs/components/select), match FieldLabel’s `htmlFor` to the trigger’s `id` and connect help or errors with `aria-describedby`.

Controls are separate exports; Field supplies their surrounding layout and text.

Connect FieldLabel through `htmlFor` and the control’s `id`. Connect help and errors through `aria-describedby`. Use `useId` for reusable field instances.

### Parts

A single field usually contains a label, one control, and optional help or error text:

```text
Field
├── FieldLabel
├── Input or another control
├── FieldDescription
└── FieldError
```

Use FieldContent to keep a label and its description together beside a checkbox, radio, or switch:

```text
Field orientation="horizontal"
├── Checkbox
└── FieldContent
    ├── FieldLabel
    ├── FieldDescription
    └── FieldError
```

For a section of related fields, FieldSet gives the section a semantic name, while FieldGroup provides spacing:

```text
FieldSet
├── FieldLegend
├── FieldDescription
└── FieldGroup
    ├── Field
    ├── FieldSeparator
    └── Field
```

Use only the parts the form needs. A checkbox with a short label does not need FieldContent. Unrelated fields can share a FieldGroup without being placed in the same FieldSet.

### Fieldsets, groups, and separators

  <FieldGrouping />
</ComponentPreview>

FieldSet renders a native `fieldset`, and FieldLegend names its contents. Use the default legend size for a form section and `variant="label"` for a smaller question or nested section. Keep the legend before the section's controls.

### Orientation

</ComponentPreview>

<include>../../../examples/field/field-horizontal.tsx</include>

| Orientation          | Use                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `vertical` (default) | Label, control, and supporting text stacked above one another. Works well for most text inputs and narrow forms.    |
| `horizontal`         | A control beside its label, or a label/description block beside a control. Useful for choices and compact settings. |

Orientation stays fixed at every viewport width. Use vertical fields when a side-by-side text input would become too cramped. FieldContent lets the label and description share a column in horizontal fields. Ajna does not expose a responsive orientation value.

### Validation and errors

<ComponentPreview>
  <FieldValidation />
</ComponentPreview>

<include>../../../examples/field/field-validation.tsx</include>

Set validation state and messages from your form logic. Field supplies presentation and accessibility hooks, not validation rules.

There are three separate connections to make:

1. `data-invalid` on Field applies the field's error presentation.
2. `aria-invalid` on the actual control exposes its invalid state.
3. `aria-describedby` references the error and any help text the user still needs.

FieldError displays a message; it does not invalidate a control. Clear the message and invalid state when the error is resolved.

#### Multiple error messages

<ComponentPreview>
  <FieldErrorMessages />
</ComponentPreview>

<include>../../../examples/field/field-error-messages.tsx</include>

Pass an `errors` array when a control can have several failures. FieldError removes duplicate messages and ignores undefined entries and empty messages. One message renders as text; several messages render as a list. With no content it renders nothing. Explicit children take precedence over the array.

### Disabled fields

<ComponentPreview>
  <FieldDisabled />
</ComponentPreview>

<include>../../../examples/field/field-disabled.tsx</include>

`data-disabled` changes FieldLabel and FieldTitle presentation. It does not disable a control. Use the control's `disabled` prop too.

A disabled FieldSet applies native disabled behavior to inputs and textareas inside it. Explicitly disable Base UI choice controls such as Checkbox, RadioGroup, and Switch as well, so their interactive roots have disabled styling and the right keyboard behavior. Disabled controls are normally excluded from form submission. Use `readOnly` instead when a supported text control should stay readable/focusable and keep its submitted value.

### Complete form

Use a real form and name submitted controls. Specify `type="submit"` or `type="reset"` on form actions; Button defaults to `type="button"`.

```tsx
"use client";

import { useId, useState } from "react";
import {
  Button,
  Checkbox,
  Input,
  Field,
  FieldSet,
  FieldLegend,
  FieldGroup,
  FieldContent,
  FieldLabel,
  FieldDescription,
  FieldSeparator,
} from "@ajnacloud/ui";

export function FieldForm() {
  const id = useId();
  const [result, setResult] = useState("");
  return (
    <form
      style={{ width: "100%", maxWidth: 420 }}
      onSubmit={(event) => {
        event.preventDefault();
        const data = new FormData(event.currentTarget);
        setResult(`Preferences received for ${data.get("name")}.`);
      }}
    >
      <FieldSet aria-describedby={`${id}-help`}>
        <FieldLegend>Profile</FieldLegend>
        <FieldDescription id={`${id}-help`}>
          Choose the details your teammates see.
        </FieldDescription>
        <FieldGroup>
          <Field>
            <FieldLabel htmlFor={`${id}-name`}>Display name</FieldLabel>
            <Input
              id={`${id}-name`}
              name="name"
              autoComplete="name"
              defaultValue="Alex Morgan"
              required
            />
          </Field>
          <Field>
            <FieldLabel htmlFor={`${id}-email`}>Work email</FieldLabel>
            <Input
              id={`${id}-email`}
              name="email"
              type="email"
              autoComplete="email"
              placeholder="alex@example.com"
              required
            />
          </Field>
          <FieldSeparator />
          <Field orientation="horizontal">
            <Checkbox
              id={`${id}-updates`}
              name="updates"
              defaultChecked
              aria-describedby={`${id}-updates-help`}
            />
            <FieldContent>
              <FieldLabel htmlFor={`${id}-updates`}>Product updates</FieldLabel>
              <FieldDescription id={`${id}-updates-help`}>
                Occasional news about new features.
              </FieldDescription>
            </FieldContent>
          </Field>
          <div style={{ display: "flex", gap: 8 }}>
            <Button type="submit" variant="primary">
              Save preferences
            </Button>
            <Button variant="secondary" type="reset" onClick={() => setResult("")}>
              Reset
            </Button>
          </div>
        </FieldGroup>
      </FieldSet>
      {result && <p role="status">{result}</p>}
    </form>
  );
}
```

A FieldGroup is a layout wrapper, not a form. Put submission on a real `form`. Use `FormData` for native-style submission, or controlled values when your application needs them. Keep server errors in application state and render them near the affected control with FieldError.

#### Form libraries

Connect your form library’s value, event, ref, and error APIs to the control, then display its messages with FieldError.

If your application already uses React Hook Form, a registered Input can be composed like this. React Hook Form is an optional application dependency (`npm install react-hook-form`), not an Ajna requirement:

```tsx
"use client";

import { useId } from "react";
import { useForm } from "react-hook-form";
import { Button, Field, FieldError, FieldLabel, Input } from "@ajnacloud/ui";

type Values = { email: string };

export function ContactForm({
  onSubmit,
}: {
  onSubmit: (values: Values) => void;
}) {
  const id = useId();
  const {
    register,
    handleSubmit,
    formState: { errors },
  } = useForm<Values>();
  return (
    <form noValidate onSubmit={handleSubmit(onSubmit)}>
      <Field data-invalid={Boolean(errors.email)}>
        <FieldLabel htmlFor={id}>Email</FieldLabel>
        <Input
          {...register("email", {
            required: "Enter your email address.",
            pattern: {
              value: /^[^@\s]+@[^@\s]+\.[^@\s]+$/,
              message: "Enter a valid email address.",
            },
          })}
          id={id}
          type="email"
          required
          aria-invalid={Boolean(errors.email)}
          aria-describedby={errors.email ? `${id}-error` : undefined}
        />
        <FieldError id={`${id}-error`} errors={[errors.email]} />
      </Field>
      <Button type="submit">Continue</Button>
    </form>
  );
}
```

For controlled Checkbox, Switch, and RadioGroup fields, adapt the library's controlled-field API to `checked`/`onCheckedChange` or `value`/`onValueChange`. Field itself does not need a controller, provider, or registration call.

### Segmented date controls

DateInput contains multiple editable segments. Give the group a visible FieldTitle and connect it with `aria-labelledby`. Use `aria-describedby` to connect help and errors. FieldLabel's `htmlFor` pattern remains appropriate for a single native Input, Textarea, or similar labelable control.

```tsx
"use client";

import { DateInput, Field, FieldDescription, FieldTitle } from "@ajnacloud/ui";
import { useId } from "react";

export function AppointmentField() {
  const id = useId();
  return (
    <Field>
      <FieldTitle id={id}>Appointment date</FieldTitle>
      <DateInput aria-labelledby={id} aria-describedby={`${id}-help`} locale="en-GB" />
      <FieldDescription id={`${id}-help`}>Type a date or choose one from the calendar.</FieldDescription>
    </Field>
  );
}
```

See [Date Input](/docs/components/date-input) for date values, forms, validation, and complete examples.

## Accessibility

- Give every control an accessible name through a real label, a wrapping choice card, or `aria-labelledby`.
- Connect help and error text through `aria-describedby`. Field does not generate those relationships automatically.
- Use FieldSet/FieldLegend for the question that applies to several controls; FieldGroup alone has no grouping semantics.
- Put required, invalid, disabled, and read-only states on the control. Field's data attributes provide presentation only.
- Preserve the controls' normal focus indicators and keyboard interactions. A Field wrapper does not create another tab stop.

Field renders `role="group"`, but that role does not automatically label its child controls. FieldTitle is a div, not a native label. FieldError defaults to `role="alert"`, so render errors when they become relevant instead of filling the page with initial alerts.

## API reference

All parts accept their rendered element's native attributes, a string `className`, `style`, and a forwarded ref. There is no `asChild` or `render` prop on Field parts. The following props are specific to the Field family.

### FieldSet

Renders `fieldset`. Use it for related controls and name it with FieldLegend. Native `disabled`, `name`, and `form` attributes remain available. Its ref targets `HTMLFieldSetElement`.

### FieldLegend

Renders `legend` inside FieldSet. Its ref targets `HTMLLegendElement`.

| Prop      | Type                  | Default    |
| --------- | --------------------- | ---------- |
| `variant` | `"legend" \| "label"` | `"legend"` |

`legend` uses section-title sizing; `label` uses the smaller field-label sizing.

### FieldGroup

Renders a div that stacks fields and nested groups. It adds spacing, not a form, validation scope, accessible name, or responsive orientation. Its ref targets `HTMLDivElement`.

### Field

Renders a div with `role="group"`. Its ref targets `HTMLDivElement`.

| Prop            | Type                            | Default      |
| --------------- | ------------------------------- | ------------ |
| `orientation`   | `"vertical" \| "horizontal"`    | `"vertical"` |
| `data-invalid`  | Boolean or data-attribute value | Unset        |
| `data-disabled` | Boolean or data-attribute value | Unset        |

Use boolean values such as `data-invalid={Boolean(error)}` for state-driven presentation.

### FieldContent

Renders a flexible div containing a label/title, description, and optional error. It keeps supporting text together beside a control in horizontal fields. Its ref targets `HTMLDivElement`.

### FieldLabel

Renders a native label. Set `htmlFor` to the control's ID, or wrap a single choice control for a selectable card. It can contain Field with FieldTitle; it must not contain another label. Its ref targets `HTMLLabelElement`.

| Prop                  | Purpose                                                               | Default                  |
| --------------------- | --------------------------------------------------------------------- | ------------------------ |
| `required`            | Show a decorative asterisk; set validation separately on the control. | false                    |
| `contextualHelp`      | Text or React content displayed in an Ajna Popover.                   | Omitted                  |
| `contextualHelpLabel` | Complete accessible name for the help button.                         | Label + More information |

Native label attributes remain supported. Help adds a surrounding label row; label props and ref still target the label itself.

### FieldTitle

Renders a div with label-like typography, useful inside a wrapping FieldLabel. It does not associate itself with a control automatically; use `aria-labelledby` when naming a control from it. Its ref targets `HTMLDivElement`.

### FieldDescription

Renders a paragraph of supporting text. It can contain links; do not place it inside a wrapping choice label when it contains interactive content. Supply an ID for `aria-describedby`. Its ref targets `HTMLParagraphElement`.

### FieldSeparator

Renders a div with a decorative line and optional centered children. It does not add an announced separator role or name a section. Its ref targets `HTMLDivElement`.

### FieldError

Renders a div with `role="alert"` when it has content, otherwise nothing. Its ref targets `HTMLDivElement`.

| Prop       | Type                                       | Default                               |
| ---------- | ------------------------------------------ | ------------------------------------- |
| `errors`   | `Array<{ message?: string } \| undefined>` | Unset                                 |
| `children` | `ReactNode`                                | Unset; takes precedence over `errors` |

Field's layout API is separate from the unstyled Base UI Field family at `/primitives/field`. Import that primitive family when you want Base UI's own validation and field-context composition.
